# OpenWRT v24/v25 升级：从 OPKG 到 APK 的架构变动

## 发生了什么？

OpenWRT 官方在 v24.10（以及开发版 v25）引入了一项巨大的架构级变动：全面废弃了原先服役多年的 `opkg` 包管理器，换用了源自 Alpine Linux 的 `apk` 包管理器（`apk-mbedtls`）。

我们在编译 x86_64 固件时遇到的 `unable to select packages` 报错，正是因为这个底层变动：

1. **包格式不兼容**：我们下载的所有第三方包（`openclash`, `argon`, `wolplus` 等）全都是传统的 `.ipk` 格式，而现在的 ImageBuilder 只认识 `.apk` 格式的包。
2. **构建索引缺失**：旧版我们使用 `opkg-make-index` 来生成本地依赖源索引，而现在的容器环境里根本没有这个命令（换成了 `apk mkndx`）。

---

## 我们的第三方依赖现状

查看 `stable/build.sh` 和 `packages/` 目录，我们目前深度依赖以下 `.ipk` 第三方包：

- `luci-theme-argon`
- `luci-app-openclash`
- `luci-app-wolplus`
- `nginx` / `ttyd` / `frpc`（这三个可能在官方源有，但被脚本设定为本地覆盖）

## 我们接下来的解决路线探讨

考虑到您之前提到过 **“现在基本不用 passwall 组件和 MosDNS 了”**，您对这些繁重的第三方包依赖或许有松动的空间。请您评估以下三种方案：

### 方案 1：暂时剥离第三方包（最快跑通新版固件）

**建议度：⭐⭐⭐⭐⭐**
在 `build.sh` 中屏蔽本地 `.ipk` 集成逻辑。由于您不需要太复杂的透明代理，基础固件出锅后，其余普通功能可以直接在软路由后台通过新的 `apk` 在线安装。

- **优点**：立刻能享受到 v25 最新内核和极致性能，告别历史包袱。
- **缺点**：缺少 Argon 主题（可能会变成官方默认的 Bootstrap 界面），需要进系统后手动摸索。

### 方案 2：回退到 v24.10.7（旧版稳定分支）

**建议度：⭐⭐⭐**
如果您必须要求刷完机就有 OpenClash 和 Argon 主题，且不想花时间折腾新版。我们可以尝试把基础镜像降级回 `openwrt-imagebuilder:x86-64-v24.10.7`。

- **优点**：一切脚本原封不动，无缝兼容 `.ipk`。
- **缺点**：无法体验最新版系统。

### 方案 3：寻找或重新编译 `.apk` 格式的第三方包

**建议度：⭐**
去各大 GitHub Repo（如 OpenClash）的 Issue 甚至 Actions 里淘宝，看看是否有先行者编译了适用于 v24/v25 的 `.apk` 包，或者我们自己拉取源码并用最新 SDK 去打包。

- **优点**：完美适配新架构。
- **缺点**：社区生态还没完全跟上，第三方包可能不稳定，甚至根本还没出 apk 版。
